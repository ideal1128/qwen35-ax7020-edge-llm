# 基于 AMD Xilinx Zynq-7020 的 Qwen3.5-0.8B 端侧大模型推理系统

> 在一块只有 **1 GB 内存**的入门级异构 SoC 上，完整跑通 0.8B 参数的大语言模型，并实现可交互的多轮对话。

**平台**：ALINX AX7020 / Xilinx Zynq-7020 (XC7Z020-2CLG400I)
　53,200 LUT · 106,400 FF · 140 BRAM36 · 220 DSP48E1 · 1 GB DDR3-1066 · 双核 Cortex-A9 @ 667 MHz
**系统**：Debian 8 (jessie) · Linux 4.9.0-xilinx armv7l · Python 3.4.2 · gcc 4.9.2
**模型**：Qwen3.5-0.8B —— 24 层（18 层 Gated DeltaNet 线性注意力 + 6 层全注意力），hidden 1024，FFN 3584
**权重格式**：BFP8 分块量化（每 64 元素共享 1 个 int8 指数 + int8 尾数，8.125 bit/元素），约 643 MB

## 二、核心工程挑战与对策

### 挑战 1：0.8B 参数装不进 1 GB 内存

原始模型 FP16 约 1.6 GB。我们采用 **BFP8 分块量化**：每 64 个权重共享一个指数，权重压到 643 MB，配合 mmap 按需分页，使模型能与 Python 运行时共存于 1 GB 内存。

### 挑战 2：算力只有 2 个 667 MHz 的 Cortex-A9

关键算子全部下沉到 **NEON 手写 C 内核**：
- GEMV（BFP8 反量化 + 点积，int32 累加）
- 因果卷积 + SiLU、FWHT64
- 注意力（QK-L2 归一化、RoPE、分页 KV cache、门控）
- GDN 递归状态更新
- 采样（top-k / top-p）

### 挑战 3：内存带宽是真正的天花板

我们实测标定了这块板子的性能边界：

| 项目 | 实测值 |
|---|---|
| DDR3 读带宽墙 | **1270.8 MB/s** |
| NEON 指令发射上限 | 1220 MB/s |
| PL 侧 AXI 实测吞吐 | 1178 MB/s（达 128-bit @100 MHz 理论峰值 1.6 GB/s 的 **74%**） |

据此判定：**纯 CPU 路径已达到该平台内存带宽的 93%**，进一步优化必须依靠 PL 硬件加速与计算/访存重叠。这个结论指导了后续 PL 加速器的设计方向。

### 挑战 4：PL 侧 GEMV 加速器

在 PL 中实现了 BFP8 GEMV 加速器（`gemv_core.v`）：16 路并行 DSP 乘加、12 级流水、64 位饱和累加器、AXI-Stream 接口，完成了 RTL 设计、testbench 验证、综合实现与时序收敛，并实测了板上 AXI 吞吐（1178 MB/s）。配套的 `gdn_core.v`、`conv1d_silu.v`、`fwht64.v`、`bfp8_pack16.v` 均已通过独立 testbench。
